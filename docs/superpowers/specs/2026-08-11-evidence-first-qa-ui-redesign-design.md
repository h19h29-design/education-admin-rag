# 근거 중심 교육행정 QA UI 개편 설계

## 목적

기존 `교육행정_AI_Launcher.html`의 어두운 네이비 기반 검색 경험을 현재 공개 QA 서비스에 적용한다. 사용자는 질문에 대한 AI 정리 답변을 먼저 읽고, 바로 아래에서 답변에 사용된 관련 사례의 실제 질의·답변과 원문 위치를 검증할 수 있어야 한다.

서비스 내부의 연결 방식, 저장소, 봇, 모델 실행 경로 및 정책 코드는 사용자 화면과 답변에 노출하지 않는다.

## 검토한 접근

1. **런처 충실형**: 중앙 검색과 카드 목록만 제공한다. 기존 파일과 가장 유사하지만 긴 AI 답변, 최근 질문, 근거 검증을 함께 다루기 어렵다.
2. **근거 중심 대화형**: 최근 질문, AI 답변, 관련 사례 질의·답변, 원문 근거를 분리한다. 검색 경험과 답변 검증을 모두 지원하므로 채택한다.
3. **집중형**: 입력과 단일 답변만 제공한다. 모바일은 단순하지만 기존 런처의 탐색성과 사례 비교 장점이 사라진다.

## 채택한 화면 구조

데스크톱에서는 3열 구조를 사용한다.

- 왼쪽: 최근 질문 목록
- 중앙 상단: 질문 입력과 추천 검색어
- 중앙 중단: 검색된 사례만 근거로 만든 AI 답변
- 중앙 하단: 관련 사례의 실제 질의·답변 목록
- 오른쪽: 답변에 사용된 사례 ID, 연도, PDF 페이지

모바일에서는 한 열로 축소한다. 최근 질문은 접을 수 있는 영역으로 이동하고, 근거 목록은 AI 답변 바로 다음에 배치한다.

관련 사례 카드는 기본적으로 제목, 연도, 페이지, 짧은 질의를 표시한다. 사용자가 펼치면 실제 질의와 사례 답변을 읽을 수 있다. AI가 생성한 문장과 원본 사례 문장은 같은 카드 안에 섞지 않는다.

## 두 가지 테마

- 밝은 테마와 어두운 테마를 동일한 정보 구조로 제공한다.
- 최초 방문에서는 `prefers-color-scheme`에 따라 선택한다.
- 사용자가 변경하면 `localStorage`에 저장하고 다음 방문에 복원한다.
- 색만 바꾸지 않고 두 테마 모두 WCAG AA 수준의 본문·버튼 대비를 유지한다.
- 기존 런처의 네이비, 파랑, 청록 계열을 어두운 테마의 기준으로 사용한다.

## 검색과 답변 데이터 흐름

1. 사용자가 질문을 제출한다.
2. 서버가 검증된 사례 검색 결과를 최대 5건까지 만든다.
3. 검색 결과가 관련성 기준을 통과하지 못하면 AI를 호출하지 않는다.
4. 관련 사례가 있으면 해당 사례 내용만 답변 입력으로 사용한다.
5. 답변 결과와 관련 사례 구조 데이터를 별도로 반환한다.
6. 화면은 AI 답변을 먼저 표시하고, 그 아래에 동일한 근거 집합의 실제 사례 질의·답변을 표시한다.

관련성 기준은 단순히 결과가 존재하는지만 보지 않는다. 정규화된 검색어 중 의미 있는 서로 다른 단어가 두 개 이상 제목·질의·답변에서 확인되거나, 네 글자 이상의 구체적인 검색어가 제목 또는 질의에서 직접 확인되어야 한다. 이 기준을 통과한 사례가 없으면 결과는 0건으로 취급한다.

## 근거 없음과 실패 처리

관련 사례가 0건이면 AI를 호출하지 않고 다음 문구만 표시한다.

> 등록된 사례집에서 이 질문과 관련된 내용을 찾지 못했습니다. 다른 표현이나 핵심어로 다시 검색해 주세요.

관련 사례는 있으나 AI 답변 생성 또는 출력 검증에 실패하면 다음 문구를 표시하고 사례 목록은 계속 제공한다.

> 답변을 정리하지 못했습니다. 관련 사례는 아래 목록에서 직접 확인해 주세요.

사용자 화면에는 예외 메시지, 내부 오류 코드, 연결 서비스명 또는 모델 응답 원문을 표시하지 않는다.

## 답변 안전 규칙

- AI는 검색 결과에 포함된 사실만 사용한다.
- 핵심 주장마다 사례 ID, 연도 및 PDF 페이지 근거가 있어야 한다.
- 근거 없는 핵심 문장, 존재하지 않는 사례 ID 또는 허용되지 않은 내부 상태 문자열이 있으면 AI 답변 전체를 거부한다.
- 거부 시 사례 목록은 유지하고 고정 실패 문구만 표시한다.
- 관련 사례 구조 데이터는 AI 문장에서 다시 추출하지 않고, 검색 결과 권한 데이터에서 직접 만든다.

## 비노출 항목

다음 내용은 화면, 진행 문구, 답변 및 사용자에게 보이는 오류에서 제거한다.

- GitLab, Webhook, Hermes, RAG 등 내부 연결·실행 서비스명
- 저장소와 프로젝트 식별자, 봇 사용자명
- `production_eligible`, `warning_code`, `complete_corpus`, `review_status` 등 내부 정책 필드
- 토큰, 요청 추적용 내부 식별자 및 시스템 프롬프트

대신 사용자에게는 다음과 같은 자연어만 표시한다.

- 진행 중: `관련 사례를 찾고 답변을 정리하고 있습니다.`
- 미검수 안내: `미검수 참고 답변입니다. 실제 업무 처리 전 최신 지침을 확인하세요.`
- 근거: 사례 ID, 연도, PDF 페이지

## 공개 응답 계약

완료 응답은 다음 사용자 데이터만 제공한다.

- 상태
- 사용자 질문 식별용 공개 요청 ID
- 검증된 AI 답변 또는 고정 안내 문구
- 관련 사례 배열: 사례 ID, 연도, PDF 페이지, 제목, 질의, 답변

내부 연결 정보와 정책 필드는 공개 응답에 포함하지 않는다. 관련 사례 필드는 개수와 문자열 길이를 제한하고, 원본 검색 결과에서 재검증한다.

## 테스트 전략

### 검색·답변 계약

- 결과 0건에서 AI 호출이 0회이고 고정 근거 없음 문구가 반환되는지 확인한다.
- 관련성 기준 미달 결과가 0건으로 처리되는지 확인한다.
- 관련 사례가 있을 때만 AI가 호출되는지 확인한다.
- AI 출력의 잘못된 사례 ID, 페이지, 내부 문자열 및 무근거 주장이 거부되는지 확인한다.
- AI 생성 실패 시 관련 사례 목록은 유지되는지 확인한다.

### 공개 API와 UI

- 완료 응답에 내부 연결명과 정책 코드가 없는지 확인한다.
- AI 답변과 관련 사례 질의·답변이 별도 영역에 표시되는지 확인한다.
- 사례 펼치기, 최근 질문 복원, 근거 링크 표시를 확인한다.
- 밝은·어두운 테마 선택과 기기 설정·저장값 복원을 확인한다.
- 데스크톱, 태블릿, 모바일에서 수평 스크롤과 잘림이 없는지 확인한다.
- 키보드 탐색, 포커스 표시, 상태 안내의 접근성을 확인한다.

## 완료 기준

- 기존 런처의 네이비 검색 경험을 계승한 근거 중심 대화형 UI가 공개 페이지에 적용된다.
- 두 테마가 정상 작동하고 선택이 유지된다.
- AI 답변 아래에 동일 근거 집합의 사례 질의·답변 목록이 표시된다.
- 관련 사례가 없으면 AI가 호출되지 않으며 지정된 고정 문구만 표시된다.
- 내부 연결 정보와 정책 코드가 사용자 화면과 답변에 나타나지 않는다.
- 기존 공개 질문 흐름, 보안 제한, 비공개 처리 및 근거 페이지 표시는 유지된다.
