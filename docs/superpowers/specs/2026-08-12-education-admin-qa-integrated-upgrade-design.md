# 교육행정 AI 통합형 검색 UI 업그레이드 설계

## 1. 목적과 결정

현재 공개 QA 화면을 `교육행정_AI_Launcher.html`보다 빠르고 명확한 업무 검색 경험으로 업그레이드한다. 첫 화면에서 17개 도구를 모두 나열하지 않고, 질문을 중심으로 다음 순서에 따라 결과를 제공한다.

1. AI가 관련 사례를 근거로 정리한 답변
2. 질문과 직접 연관된 실행 가능한 업무 도구
3. 관련도순 사례 질의·답변 최대 20건

채택한 방향은 **답변 중심 통합형**이다. 단순 대화형보다 사례와 도구의 가치를 잘 보여주고, 도구 카탈로그형보다 사용자가 선택해야 하는 부담이 적다.

이 설계는 2026-08-11 근거 중심 QA UI 설계를 대체한다. 특히 고정 3열 레이아웃, 5건 결과 제한, 사례 ID 노출을 폐기하고 모바일 우선 단일 흐름, 최대 20건, 연도·PDF 쪽만 표시하는 계약을 사용한다.

## 2. 사용자 목표와 성공 기준

사용자는 교육행정 용어를 정확한 문장으로 작성하지 않아도 된다. `계약`, `물품`, `복무`, `휴가`, `계약 물품`처럼 짧게 입력해도 해당 단어가 실제 질의·답변에 있는 사례를 찾을 수 있어야 한다.

성공 기준은 다음과 같다.

- 첫 진입 후 검색 입력까지 별도 탐색이 필요하지 않다.
- 한 개의 짧은 업무 키워드도 실제 일치 사례가 있으면 0건으로 제거하지 않는다.
- 답변과 사례가 같은 근거 집합을 사용한다.
- 관련 사례는 관련도순을 유지하며 최대 20건 모두 접근할 수 있다.
- 출처는 `2020년 · PDF 242쪽` 형식만 보인다.
- 내부 연결 서비스, 저장소, 봇, 모델, 사례 ID 및 정책 필드는 보이지 않는다.
- 데스크톱과 모바일 모두 핵심 동선이 질문 → 답변 → 도구 → 사례 순서다.
- 완료되지 않은 요청은 영구적인 `답변 준비 중`으로 남지 않는다.

## 3. 화면 구조

### 3.1 공통 헤더

헤더는 브랜드, 두 개의 테마 전환, 최근 질문 진입점만 둔다. 개인정보 입력 금지 안내는 검색 영역 가까이에 짧게 표시한다. 내부 시스템 상태나 연결 대상을 나타내는 배지는 두지 않는다.

최근 질문은 데스크톱 고정 좌측 패널 대신 서랍 또는 팝오버로 연다. 모바일에서는 같은 목록을 전체 너비 시트로 연다. 이 변경으로 첫 화면의 검색 폭을 확보하고 결과 읽기에 집중한다.

### 3.2 첫 화면

첫 화면은 최대 너비가 제한된 단일 열로 구성한다.

- `2020–2025 사례집 기반` 범위 안내
- `질문 하나로 답과 사례까지` 제목
- 한 줄 중심 검색 입력과 명확한 검색 버튼
- `짧은 단어도 괜찮습니다` 안내
- 수의계약, 물품구매, 휴가·복무, 시간외근무 등 소수의 추천 검색 칩
- 개인정보 입력 금지 안내

연도·분야 필터와 외부 서비스 링크를 첫 화면에 상시 나열하지 않는다. 필요한 필터는 검색 결과에서 결과 좁히기 칩으로 제공한다.

### 3.3 결과 화면

검색 후에도 상단에 입력값과 `다시 검색` 동작을 유지한다. 결과 본문은 다음 순서다.

1. **AI 답변 카드**: 검증된 사례만 사용한 짧은 답변과 연도·PDF 쪽 근거
2. **관련 업무 도구 카드**: 실제 실행 가능한 도구가 질문과 연결될 때만 최대 2개
3. **관련 사례 목록**: 관련도순 최대 20건

사례 카드는 번호, 제목, 질의 미리보기, 연도·PDF 쪽을 기본으로 보여준다. 펼치면 질의와 답변 전문을 분리된 영역에서 제공한다. 처음 세 사례는 시각적으로 우선되지만 나머지 사례도 같은 페이지에 축약 카드로 모두 렌더링한다. `전체 펼치기`는 선택 기능이며 결과를 추가로 가져오는 동작이 아니다.

기존 우측 `답변 근거` 패널은 제거한다. 출처를 AI 문단과 사례 카드에 직접 배치해 중복 정보와 좁은 본문 폭을 줄인다.

### 3.4 두 가지 테마와 반응형

밝은 테마와 어두운 테마만 제공한다. 저장된 선택을 우선하고, 저장값이 없으면 기기 설정을 따른다. 두 테마는 동일한 정보 구조를 가지며 색 외에 상태 의미를 전달하는 텍스트·아이콘을 함께 사용한다.

- 데스크톱: 결과 본문 최대 너비 약 1,100px, 답변과 도구는 균형 잡힌 2열 사용 가능
- 태블릿: 단일 결과 열, 도구 카드 2열
- 모바일: 완전한 단일 열, 검색 버튼과 사례 펼치기 터치 영역 최소 44px

가로 스크롤, 잘린 사례 메타데이터, 화면 밖 고정 패널은 허용하지 않는다.

## 4. 검색 동작

### 4.1 입력 정규화

질문은 기존 공개 입력 계약을 유지한다.

- 앞뒤 공백 제거 및 연속 공백 축약
- NFC 정규화
- 최대 1,000자
- 허용되지 않은 제어문자 입력 거부

AI를 사용해 검색어를 임의로 재작성하지 않는다. 원 질문과 검색 결과의 추적 가능성을 유지한다.

### 4.2 짧은 검색어

검색 백엔드는 현재의 정확 토큰과 한글 문자 n-그램 순위를 유지한다. 공개 사례 필터는 다음 규칙을 적용한다.

- 의미 있는 토큰이 하나뿐이면, 그 토큰 전체가 제목·질의·답변 중 하나에 실제 포함된 사례를 유지한다.
- 의미 있는 토큰이 둘 이상이면 서로 다른 토큰 두 개 이상이 실제 포함되거나, 네 글자 이상의 구체적인 토큰 하나가 직접 일치한 사례를 유지한다.
- 검색 백엔드의 순서를 바꾸지 않고 중복 사례만 제거한다.

따라서 `계약`, `물품`, `복무`, `휴가`는 한 단어 검색으로 동작하고, `계약 물품`은 두 단어가 모두 포함된 사례를 우선 제공한다. 단순 부분 문자열이나 한 글자만 같은 결과는 유지하지 않는다.

### 4.3 넓은 검색과 결과 좁히기

한 단어 검색은 결과가 넓을 수 있으므로 답변 위에 `넓은 검색 결과` 안내와 검토된 분야 칩을 제공한다. 예를 들어 `계약`은 물품구매, 수의계약, 공사, 용역 칩을 제공할 수 있다.

칩은 운영자가 검토한 제한된 매핑만 사용한다. AI가 임의로 칩을 만들거나 검색어를 보이지 않게 확장하지 않는다. 칩을 누르면 검색 입력에 명시적으로 단어가 추가되어 사용자가 변경을 확인할 수 있다.

### 4.4 근거 없음

공개 필터까지 통과한 사례가 0건일 때만 AI를 호출하지 않고 다음 문구를 표시한다.

> 등록된 사례집에서 이 질문과 관련된 내용을 찾지 못했습니다. 다른 표현이나 핵심어로 다시 검색해 주세요.

검색 실패, 대기 시간 초과, 응답 형식 오류를 사례 없음으로 위장하지 않는다. 각 상태는 별도의 고정 사용자 문구를 사용한다.

## 5. AI 답변과 사례 계약

AI는 공개 필터를 통과한 최대 20개 사례만 입력으로 받는다. 답변의 각 문단에는 허용된 `연도 · PDF 쪽` 근거가 하나 이상 있어야 한다. 근거 없는 문단, 허용되지 않은 페이지, 내부 서비스명 또는 사례 ID가 있으면 AI 문장만 거부하고 사례 목록은 보존한다.

AI 답변 검증에 실패했을 때는 다음 문구를 표시한다.

> 답변을 정리하지 못했습니다. 관련 사례는 아래 목록에서 직접 확인해 주세요.

사례 제목·질의·답변과 출처는 AI 출력에서 다시 추출하지 않고 검색 권한 데이터에서 직접 렌더링한다.

## 6. 관련 업무 도구

도구는 질문보다 먼저 선택하게 하지 않는다. 검색 결과에 따라 보조 행동으로 제공한다.

- 운영 확인이 끝난 실행 가능 도구만 표시한다.
- `설계 미리보기` 상태의 도구는 공개 결과에 표시하지 않는다.
- 한 결과에 최대 2개만 표시한다.
- 질문 토큰과 검토된 분야·도구 매핑으로 결정하며 AI 자유 생성 추천은 사용하지 않는다.
- 해당 도구가 없거나 실행 상태를 검증할 수 없으면 영역 전체를 숨긴다.

첫 구현 범위는 기존에 실제 동작하는 도구로 연결하는 것까지다. 새 계산기나 판정기의 업무 규칙을 만드는 작업은 별도 검증 과제로 분리한다.

## 7. 최근 질문과 대기 상태

최근 질문은 이 기기에서만 최대 12개를 저장한다. 질문 본문, 공개 요청 ID, 공개 poll token, 생성 시각, 공개 완료 결과만 저장하며 내부 상태나 비밀은 저장하지 않는다.

대기 상태는 다음과 같이 변경한다.

- 제출 직후: `답변 준비 중`
- 5분 이내 완료: `검색 완료`
- 5분 초과 또는 반복 확인 실패: `다시 검색 필요`

`다시 검색 필요` 항목은 동일 질문을 입력란에 복원하고 새 요청을 생성하는 버튼을 제공한다. 기존 요청을 계속 무한 확인하거나 과거 비공개 이슈를 재사용하지 않는다.

## 8. 오류 처리

사용자 상태를 네 종류로 분리한다.

1. 사례 없음: 고정된 사례 없음 문구
2. AI 답변 검증 실패: 사례 목록 유지, 답변 정리 실패 문구
3. 요청 접수 실패: `질문을 접수하지 못했습니다. 잠시 후 다시 시도해 주세요.`
4. 대기 시간 초과: `답변이 지연되었습니다. 같은 질문으로 다시 검색해 주세요.`

예외 문자열, 내부 오류 코드, 서비스명, 모델 출력 원문, 저장소 식별자, 봇 사용자명은 UI와 공개 API에 포함하지 않는다.

## 9. 컴포넌트 경계

### 공개 Worker

- 질문 접수, 사람 확인, 공개 poll token, 고정 오류 응답을 담당한다.
- 완료 응답에서 공개 필드와 최대 20건 제한을 재검증한다.
- 검색 순위나 관련성 판단을 새로 만들지 않는다.

### 맥미니 검색·응답 브리지

- 권한이 고정된 검색기를 실행한다.
- 짧은 키워드 포함 관련성 규칙을 적용한다.
- 근거가 있을 때만 AI 답변을 요청한다.
- 검증된 공개 답변과 사례 구조만 게시한다.

### 브라우저 UI

- 공개 응답을 다시 엄격하게 검증한다.
- AI 답변, 도구, 사례를 별도 컴포넌트로 렌더링한다.
- 테마, 최근 질문, 대기 만료와 재검색 상호작용을 담당한다.
- 검색 결과나 근거를 브라우저에서 추론하지 않는다.

## 10. 접근성·성능·보안

### 접근성

- 한 페이지에 하나의 `h1`과 논리적인 제목 계층을 사용한다.
- 진행 상태는 `aria-live`로 알리고, 사례는 키보드로 펼칠 수 있는 네이티브 `details`를 유지한다.
- 포커스 표시를 제거하지 않으며 두 테마 모두 본문과 버튼 대비를 확인한다.
- 모션 감소 설정에서 불필요한 전환 효과를 제거한다.

### 성능

- 웹폰트와 대형 이미지 의존을 추가하지 않는다.
- 첫 화면 정적 자산은 현재 Worker assets에서 제공한다.
- 사례 20건은 접힌 카드로 한 번 렌더링하되 전문은 이미 받은 공개 데이터만 사용하고 추가 네트워크 요청을 만들지 않는다.
- 레이아웃 이동을 줄이기 위해 진행·결과 영역의 최소 높이를 확보한다.

### 보안과 개인정보

- 기존 Turnstile/자체 접속 확인, 출처 검증, confidential 질문 처리, origin 검증을 유지한다.
- 사용자 질문과 사례 원문을 분석·추적 서비스로 전송하지 않는다.
- 내부 연결 정보, 비밀, 시스템 프롬프트 및 비공개 필드는 DOM 속성·주석·오류에도 넣지 않는다.

## 11. 테스트 전략

### 검색과 관련성

- `계약`, `물품`, `복무`, `휴가` 각각 백엔드 결과가 있고 전체 토큰이 일치하면 사례가 유지되는지 확인한다.
- 한 글자 부분 일치와 무관한 결과가 제거되는지 확인한다.
- `계약 물품`처럼 두 단어 검색에서 두 토큰 일치 사례가 유지되는지 확인한다.
- 순서와 최대 20건 제한이 유지되는지 확인한다.

### 공개 응답과 안전

- 사례 없음, AI 검증 실패, 접수 실패, 시간 초과를 서로 다른 응답으로 확인한다.
- 사례 ID와 내부 연결명·정책 필드가 공개 JSON 및 DOM에 없는지 확인한다.
- 답변 문단의 연도·페이지 근거 검증과 잘못된 근거 거부를 확인한다.

### UI

- 첫 화면 검색, 추천 칩, 결과의 답변→도구→사례 순서를 확인한다.
- 20개 사례가 관련도순으로 모두 렌더링되고 질의·답변을 펼칠 수 있는지 확인한다.
- 도구가 없을 때 빈 영역이 남지 않는지 확인한다.
- 최근 질문 복원과 5분 만료 후 재검색 전환을 가짜 시계로 확인한다.
- 390px, 768px, 1280px 뷰포트에서 수평 스크롤과 잘림을 확인한다.
- 키보드 전용 탐색, 접근 가능한 이름, 포커스 및 `aria-live`를 확인한다.

### 운영 왕복

- 운영 화면에서 `계약`, `계약 물품`, 구체적인 문장, 근거 없는 질문을 각각 한 번 검증한다.
- 완료 결과가 AI 답변과 최대 20개 사례를 표시하는지 확인한다.
- 5분 이상 완료되지 않는 테스트 요청이 `다시 검색 필요`로 바뀌는지 확인한다.

## 12. 완료 기준

- 추천안 B의 첫 화면과 결과 화면이 밝은·어두운 두 테마로 배포된다.
- 짧은 한 단어 검색이 실제 일치 사례를 최대 20건까지 반환한다.
- AI 답변, 실행 가능한 관련 도구, 관련 사례가 정해진 순서로 보인다.
- 중복 근거 패널과 상시 도구 카탈로그가 제거된다.
- 오래된 대기 질문이 영구 pending으로 남지 않고 재검색할 수 있다.
- 모바일·태블릿·데스크톱 및 키보드 접근성 검증을 통과한다.
- 내부 연결 정보와 사례 ID가 공개 화면 및 답변에 노출되지 않는다.
- 기존 질문 접수, 비공개 처리, 사람 확인 및 출처 검증 계약을 유지한다.
