# 서울 주소 별칭 좌표 복구 설계

## 목적

운영 후보 `20260814T123000Z`는 학교 수 모집단 대조를 통과했지만, 좌표가 있는
선택 가능 기관이 `1,992 / 2,143 = 92.95%`에 그쳐 필수 품질 기준 98%에서
차단되었다. 이 설계는 품질 기준을 낮추거나 퍼지 매칭을 도입하지 않고,
도로명 주소의 서울 광역자치단체 표기인 `서울특별시`, `서울시`, `서울`만
동일한 별칭으로 취급해 카카오 주소 검색 결과를 보수적으로 수용한다.

동기화는 계속 후보만 생성한다. 이 변경은 기존 후보를 수정하거나
`current.json`을 생성하지 않으며, 새 후보가 모든 품질 gate를 통과해도 별도의
검토 패킷, review digest, `data-steward` 승인을 거쳐야 한다.

## 근거와 현재 차단 상태

승인되지 않은 후보를 기관명·주소 원문 없이 집계한 결과는 다음과 같다.

| 항목 | 건수 |
| --- | ---: |
| 전체 좌표 누락 사이트 | 161 |
| NEIS | 118 |
| 서울시교육청 검수 CSV | 42 |
| 유치원알리미 | 1 |
| `서울특별시 ...`로 시작하는 누락 주소 | 159 |
| 경기도 주소 | 1 |
| 기타 주소 | 1 |
| 기존 카카오 exact 수용 | 9 |

기존에 수용된 9건은 모두 `서울 ...` 형식이다. 현재 카카오 클라이언트는 공백만
정규화한 뒤 요청 주소와 응답 `road_address.address_name`을 완전 문자열 비교한다.
따라서 원천의 `서울특별시 ...`와 카카오의 `서울 ...`가 같은 도로명·건물번호를
가져도 불일치한다.

98%를 통과하려면 현재 1,992개에서 최소 109개가 추가로 `ACTIVE`가 되어야 한다.
누락 중 서울 주소이고 기본 사이트이며 `UNCLASSIFIED_SCHOOL`이 아닌 대상은
140개이므로, 이 중 최소 109개(77.86%)가 안전하게 단일 일치해야 한다. 복구율이
이에 못 미치면 gate는 그대로 실패해야 한다.

카카오 공식 주소 검색 문서는 주소 질의 결과로 지번·도로명 주소와 좌표를
제공하며, 응답의 전체 도로명 주소가 축약된 광역자치단체 표기를 사용할 수 있다.
상세 주소나 건물명을 제거한 별도 질의, 키워드 검색, 좌표 추정은 이 설계에
포함하지 않는다.

## 범위와 비범위

- 범위: 서울 광역자치단체 이름의 제한된 canonicalization, 단일 exact 도로명
  결과 선택, 좌표·provenance·품질 gate 회귀 검증, 관리자 문서 갱신.
- 비범위: 도로명·건물번호 완화, 문자열 유사도, 키워드 장소 검색, 두 번째 API
  요청, 수동 좌표 리소스, 98% 기준 완화, 기존 후보 수정, 자동 검토·승인·배포.

## 주소 동등성 규칙

새 private helper는 exact built-in `str`만 받고 다음 순서로 canonical 문자열을
만든다.

1. 연속 공백을 한 칸으로 합치고 앞뒤 공백을 제거한다.
2. 첫 토큰이 정확히 `서울특별시`, `서울시`, `서울` 중 하나면 `서울`로 바꾼다.
3. 나머지 토큰은 삭제·치환·Unicode 변환 없이 그대로 둔다.
4. 서울 토큰이 아닌 주소는 기존 공백 정규화 결과를 그대로 사용한다.

따라서 다음만 동등하다.

```text
서울특별시 종로구 송월길 48
서울시 종로구 송월길 48
서울 종로구 송월길 48
```

다음 차이는 계속 불일치다.

- 도로명 또는 건물번호 차이
- 상세 건물명·괄호·쉼표의 추가 또는 제거
- 구 이름 차이
- `서울특별시`가 첫 토큰이 아닌 경우
- 서울과 경기 등 다른 시·도 간 변환
- Unicode 호환문자나 오탈자

## 카카오 결과 선택

`KakaoLocalClient.geocode()`는 기존 한 번의 주소 검색 요청과 응답 크기·횟수
제한을 유지한다. 응답 `documents`의 각 항목에 대해 `road_address`가 정확한
객체이고 `address_name`이 canonical nonblank 문자열일 때만 비교한다.

- canonical 도로명 주소가 요청과 같은 결과가 정확히 1개면 해당 결과를 선택한다.
- 0개 또는 2개 이상이면 `None`을 반환하고 좌표를 채우지 않는다.
- 선택된 결과의 `x`, `y`가 finite WGS84 범위가 아니면 안전한 원천 오류로
  실패한다.
- 반환 `road_address`는 원천 입력 주소를 공백 정규화한 값으로 유지한다. 원천
  주소를 카카오 표기로 덮어쓰지 않는다.
- 서울 경계 검증은 후보 생성 시 기존 `CoverageService`가 다시 수행한다.
- 경기도의 검토 대상 등 서울 외 기관은 이 변경으로 `ACTIVE`가 되지 않는다.

`analyze_type`, 키워드 검색, 페이지 추가 조회 또는 fallback 질의는 추가하지
않는다. API 호출 수는 기존과 동일하며, 이미 사용된 두 번의 운영 동기화 권한은
재사용하지 않는다.

## 데이터 흐름과 감사 경계

```text
원천 주소
  -> 기존 1회 Kakao 주소 검색
  -> 요청/응답 도로명 주소의 제한된 서울 별칭 canonicalization
  -> exact 결과가 하나인지 확인
  -> 좌표 숫자 검증
  -> 후보의 서울 CoverageState 검증
  -> 98% 품질 gate
  -> 사람 검토 패킷 및 별도 승인
```

기존 `EnrichmentProvenance`의 요청 수, 수용 수, raw SHA-256, normalized SHA-256가
감사 근거다. 로그와 문서에는 전체 요청·단일 일치·미일치와 좌표 품질의 집계만
남기며 기관명, 주소, 좌표, 응답 원문, API 키를 출력하지 않는다. provenance의
수용 레코드 hash는 canonicalization 후 실제 수용된 결과 집합에 계속 결합된다.

## 실패 동작과 운영 절차

다음 조건이면 fail-closed 동작을 유지한다.

1. 카카오 응답 스키마가 잘못되거나 제한을 초과한다.
2. canonical exact 결과가 없거나 복수다.
3. 좌표가 유한하지 않거나 WGS84 범위를 벗어난다.
4. 좌표가 서울 coverage 밖이다.
5. 최종 선택 가능 기관 좌표 성공률이 98% 미만이다.
6. provenance, 후보, transaction 또는 review digest가 일치하지 않는다.

구현과 오프라인 검증이 끝나도 운영 동기화는 자동 실행하지 않는다. 관리자가
비용·호출·키 사용을 포함해 새 candidate-only 동기화 1회를 별도로 승인해야 한다.
새 후보가 98%를 통과하면 관리자 전용 review CLI로 집계를 확인하고, 복사한 exact
review digest를 별도 approval CLI에 전달한다. 승인 전에는 release gate가 계속
차단되어야 한다.

## 검증 전략

TDD 회귀 테스트로 다음을 고정한다.

1. `서울특별시`, `서울시`, `서울`의 동일 도로명·건물번호는 서로 동등하다.
2. 공백 차이는 허용하지만 도로명·번호·구·시도·상세 문자열 차이는 거부한다.
3. 카카오가 `서울 ...`로 반환한 한 개의 exact 결과가 `서울특별시 ...` 요청을
   안전하게 채운다.
4. exact 결과 0개·복수, `road_address` 누락, 좌표 오류는 기존처럼 실패하거나
   미일치로 남는다.
5. 한 입력당 요청은 정확히 한 번이고, 키워드/fallback 요청은 발생하지 않는다.
6. provenance의 fetched/matched 건수와 normalized hash가 실제 수용 결과와
   일치한다.
7. 후보 품질 gate는 98%를 그대로 요구하며 97.99%를 거부한다.
8. 운영 후보, transaction, `current.json`, 비밀값이 테스트나 커밋에 포함되지
   않는다.
9. 전체 Python warning-strict, Ruff, mypy, Playwright, release fail-closed 검증을
   통과한다.

## 승인 기준

이 설계는 주소 의미를 추정하는 일반 퍼지 매칭이 아니다. 대한민국 서울의 공식명,
통용 축약명만 첫 토큰에서 canonicalize하고 나머지 도로명 주소를 완전 일치시키는
제한된 호환성 수정이다. 구현 후에도 98%를 통과하지 못하면 좌표를 임의 채우거나
기준을 낮추지 않고, 수동 검수 리소스를 별도 설계로 제안한다.
